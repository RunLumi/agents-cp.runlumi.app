# Contract / Plan Change Request — P06-CR-003

## Trigger

P02 already exposes a reauthenticated organization deletion lifecycle route, while F20 requires asynchronous, auditable, resumable deletion. The initial P06 draft proposed a second `/deletions` POST route and introduced R2 export storage without a durable storage/access decision. Existing P01–P05 immutable foreign keys also mean physical deletion cannot be the default for audit, usage, cost, and security history.

## Affected phase and packets

- Phase: P06
- Contract Gate: `p06-cg-v1` draft
- Active dependent packets: P06-MOD-03, P06-BE-04, P06-FE-04, P06-QA-01
- Merged dependent packets: none

## Proposed change

Current: A new organization deletion POST route and unspecified R2 artifact access/storage model.

New: Keep `POST /api/v1/orgs/{org_id}/deletion` as the sole organization deletion request. Extend it transactionally to create/link a P06 `DeletionJob` after reauthentication and typed confirmation. Use a private R2 binding for export objects with Worker-mediated, re-authorized, short-lived download access; D1 stores metadata only. Deletion jobs tombstone/minimize immutable history and traverse object/cache/index/derived references where those systems exist.

## Why this is necessary

This avoids bypassing P02 lifecycle authorization, prevents permanent public artifact URLs, and makes partial deletion/retry observable. It aligns F20's legal/security retention allowance with the existing immutable P01–P05 schema.

## Compatibility impact

- API: existing organization lifecycle route remains; new job status/resume and personal account data routes are additive.
- schema: additive export/deletion job tables and R2 object metadata; immutable audit/usage rows are not rewritten.
- FE fixtures/types: show job progress, legal retention, and resumable failure.
- LumiAgents protocol: no protocol change; local ZCode data is not claimed deleted by cloud jobs.
- migrations: `0014` is additive; rollback disables workers and retains metadata/objects until lifecycle expiry.
- security: downloads reauthorize principal, scope, state, and expiry; R2 bucket is private.
- existing data: organization `pending_deletion` rows are discoverable for job attachment; no blind cascade.

## Alternatives considered

1. Add a second `/orgs/{org_id}/deletions` POST route; rejected because it duplicates P02 and can bypass lifecycle checks.
2. Public R2 URLs or permanent presigned links; rejected because they are bearer credentials and weaken tenant isolation.
3. Physical deletion of all immutable audit/usage rows; rejected because it breaks audit and accounting obligations.
