# Contract / Plan Change Request — P06-CR-001

## Trigger

The initial P06 contract draft used an absolute “two devices can never execute the same leased occurrence” guarantee and modeled ZCode off-peak work as a cron window. Implementation reconnaissance shows that an expired lease after a network partition cannot prove whether a disconnected host already started side effects, and the current ZCode off-peak path is a distinct provider-ticket/no-clock execution class. Interval rules also need calendar units/DST semantics rather than only `every_seconds`.

## Affected phase and packets

- Phase: P06
- Contract Gate: `p06-cg-v1` draft
- Active dependent packets: P06-MOD-01, P06-BE-01, P06-INT-01, P06-QA-01
- Merged dependent packets: none

## Proposed change

Current: Lease expiry requeues an occurrence; off-peak is represented as a schedule window; intervals are elapsed seconds.

New: Freeze at-most-one current server-authorized lease. A lease that may have started execution becomes `ambiguous` and is never automatically re-dispatched; only proven-not-started leases may requeue. Add explicit claim/renew/start/settle/release operations. Model off-peak as a provider-ticket/no-clock execution class with recursive/background-process restrictions. Normalize intervals to minutes/hours/days/weeks/months/years with timezone/DST rules and bounded catch-up.

## Why this is necessary

These changes preserve F15's safety intent while matching the distributed runtime and existing ZCode behavior. They prevent a second device from receiving work after a partition while avoiding a false promise that the control plane can stop an already-running local process.

## Compatibility impact

- API: additive device start/renew/settle/release routes and `ambiguous` state; existing P05 run routes remain authoritative.
- schema: additive occurrence/lease states and run correlation; no existing rows are rewritten.
- FE fixtures/types: add ambiguous/reconciliation and off-peak/interval states.
- LumiAgents protocol: lease claim/start/settle/release and provider-ticket off-peak context.
- migrations: `0011` remains additive; no destructive migration.
- security: current policy, principal, and device are rechecked at each transition.
- existing data: no P06 implementation data exists yet; imported ZCode off-peak tasks are not silently converted to cron.

## Alternatives considered

1. Keep absolute simultaneous-execution wording and require a hosted online side-effect broker; rejected for P06 because the current local execution host cannot be made continuously reachable by the Worker.
2. Convert off-peak work into normal scheduled automations; rejected because it erases ZCode safety and provider-ticket semantics.
