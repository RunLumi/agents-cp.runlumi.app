# Change Request — P04-CR-001: reserve migration number with P03

- Status: accepted by P04 coordinator
- Affected phase: P04
- Related frozen contract: `p04-cg-v1`
- Related phase contract: `p03-cg-v1`

## Context

P03-CG reserves additive migration `0007_p03_devices_projects_policy.sql` for the device, project, and policy snapshot substrate. P04's initial implementation was drafted as `0007_p04_ai_platform.sql` before the P03 migration was present in the synchronized tree. Applying both under the same number would make fresh-environment migration order ambiguous and could cause one phase's schema to be skipped.

## Decision

P04 uses `0009_p04_ai_platform.sql`. Existing `0008_p02_authenticators.sql` remains unchanged. P03 retains ownership of `0007`; P04 does not edit, rename, or depend on P03 tables. The P04 migration remains additive and can be applied after the P03 and P02 auth migrations.

## Compatibility impact

- No API or wire-contract change.
- No entity or permission change.
- Fresh databases apply migrations in numeric order; already-initialized local databases must record the new migration before applying it.
- P04 continues to expose only its own catalog/credential/route/usage tables; the optional P03 policy snapshot adapter remains an extension point.

## Verification

- `wrangler d1 migrations list DB --local --env development` shows no duplicate migration name.
- P04 smoke applies the AI schema and completes the managed streaming slice.
- P03 coordinator must run its own migration verification after merging its `0007` file.
