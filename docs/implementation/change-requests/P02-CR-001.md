# Contract / Plan Change Request — P02-CR-001

## Trigger
The first implementation pass exposed security-critical details that were implicit in the P02-CG prose but not explicit enough for parallel packets: cookie/CSRF and secret replay behavior, bounded auth rate limits, exact org-header mismatch handling, identity-link confirmation, invitation lifecycle endpoints, and a lifecycle permission needed to recover a suspended organization.

## Affected phase and packets
- Phase: P02
- Contract Gate: `p02-cg-v1` (`ba35fb6`)
- Active dependent packets: P02-BE-01/02/03/04, P02-FE-01/02/03, P02-INT-01
- Merged dependent packets: none

## Proposed change
Current: P02-CG names the entities and broad API surfaces but leaves transport/security details implicit.

New: explicitly freeze `lumi_session`/`lumi_csrf` cookie behavior, 30-day revocable session rotation, double-submit CSRF, 15-minute D1 auth rate-limit buckets, `X-Org-ID` exact-match behavior, reauth-bound identity linking, invitation list/revoke/resend, owner-only `org.lifecycle` recovery transitions, and the complete role/permission matrix. P02 remains `p02-cg-v1` because these are clarifications of existing MUSTs, not breaking API changes.

## Why this is necessary
The implementation must not persist raw auth/invitation/device secrets in P01 idempotency response bodies, trust stale claims, or make a suspended organization impossible to recover. Making these choices explicit prevents FE/BE/INT packets from inventing incompatible behavior.

## Compatibility impact
- API: additive routes/fields only; P01 envelopes unchanged.
- Schema: additive P02 tables/constraints and a bounded rate-limit table.
- FE fixtures: auth, org, invitation, and account fixtures gain explicit reason/cookie behavior.
- LumiAgents protocol: unchanged except documented PKCE handoff fields.
- Migrations: append-only P02 migrations; existing data is not reinterpreted.
- Security: stronger fail-closed behavior; no secret is newly exposed.

## Alternatives considered
1. Store raw secrets in P01 idempotency rows — rejected because retries would persist/replay credentials.
2. Let every client choose an org header without a path — rejected because it permits ambiguous context.
3. Defer lifecycle recovery — rejected because it leaves suspended tenants without a safe owner path.
