# Change Request — P04-CR-002: clarify P04 additive safety semantics

- Status: accepted by P04 coordinator
- Affected phase: P04
- Related frozen contract: `p04-cg-v1` (`57b2df9`)
- Related change request: `P04-CR-001`

## Context

The vertical slice exposed several additive implementation details that were not explicit in the original gate text: draft route versions must remain distinguishable from published immutable versions, policy reads need an explicit unrestricted-versus-deny representation, provider health needs bounded rolling counters, and vulnerable mutations need durable idempotency projections.

## Clarifications

These are additive clarifications and do not remove or rename a public entity, endpoint, permission, or event:

1. `routes` remain organization-scoped; draft `route_versions` have `published_at = NULL`. Publishing creates a new immutable published version pointer, and rollback accepts only published targets.
2. An unconfigured development policy may use unrestricted `null` allowlists for local fixtures. Production and malformed explicit policy data fail closed; an explicit empty array is deny-all.
3. Provider health stores bounded counters and latency totals alongside the current cooldown state. Credential/request-specific failures are tenant-scoped degraded observations; provider transport failures may create a bounded cooldown.
4. Route, credential, policy, catalog lifecycle, and rotation mutations use the shared scoped idempotency projection. Conditional version guards prevent a successful replay projection from committing a stale write. P04 rotation is immediate-revoke; configurable overlap/in-flight rotation remains a P05 extension.
5. The native gateway propagates the server request ID to upstream adapters, waits for a meaningful text/tool event before committing a stream, rejects non-stream upstream error bodies, and translates Anthropic request/stream events behind the vendor-neutral envelope. A stream drop/abort guard schedules cancellation finalization when the Worker delivers a disconnect.
6. P03's frozen opaque `models.schema_version: 0` placeholder is a no-op model-policy section; malformed P04-shaped sections still fail closed. Local-only credential metadata is creator-scoped and excluded from organization enumeration; it is never a managed secret source.
7. The merged organization policy read returns the P04 model-policy view even when no device snapshot has been published, marking that state with `persisted: false`; the P03 inspector renders it as empty, while a persisted P03 snapshot remains authoritative when present.

## Compatibility

No desktop release is required for route changes. P03 remains the owner of device/project policy transport; the merged P03 organization policy route now returns the P04 model-policy view alongside the versioned snapshot, and P04 resolves the latest persisted snapshot server-side after authorization. The external LumiAgents checkout also contains a runtime-only managed-inference config/mapping boundary; desktop rollout remains downstream integration work.
