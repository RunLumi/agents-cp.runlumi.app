# P05 Change Request — P05-CR-001

- Status: accepted
- Date: 2026-09-25
- Requested by: P05 coordinator
- Affected contract: `p05-cg-v1`
- Scope: clarification only; no state/API/persistence behavior changes

## Problem

The frozen P05 examples used human-readable fixture tool keys such as `tool_readonly_repo`, while the shared ID convention and migration require opaque `<prefix>_<32 lowercase hex>` identifiers. The MCP wire/database naming also needed an explicit mapping.

## Resolution

1. Tool and capability identifiers are opaque IDs. P05 fixtures and documentation must use valid `tool_`/`cap_` IDs; human-readable labels belong only in `name`/display fields.
2. `McpRegistration` is exposed as `mcp_id` on the wire and stored as `mcp_registration_id` in D1. This is a field-name mapping, not a second resource.
3. Tool fingerprints, not display names, bind approvals and re-review.

## Compatibility

No existing P01–P04 contract changes. FE/BE/INT packets must regenerate fixtures and decoders against the clarified names. No implementation packet may use the symbolic fixture keys as persisted IDs.

## Verification

- `0010_p05_runs_tools_usage_control.sql` parses with SQLite/D1 migration smoke.
- P05 domain/API tests assert valid opaque IDs and reject malformed prefixes.
