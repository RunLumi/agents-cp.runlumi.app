## Outcome

The LumiAgents/ZCode managed client sends stable org, project, device, agent-session, run, agent-definition/version, and request correlation identity to the control plane without treating client IDs as authorization.

## In scope

- Runtime-only managed-run context type and serialization.
- Device-token/session correlation through the client/provider boundary.
- P05 run start and P04 inference correlation fields.
- External ZCode task/session ID preservation.
- Compatibility fallback for unmanaged/local execution.

## Explicitly out of scope

- Tool execution, approval UI, policy decisions, and provider-specific implementation.

## Frozen contracts consumed

- API: P05-CG run/inference identity fields and P03 device routes.
- Entities: `rse_`, `run_`, `agd_`, `dvc_`, `req_`.
- Permissions: P03 device token, `runs.start`, `inference.use`.
- Events: all P05 run/inference events.
- Policy schema: current P03 snapshot; no client-supplied policy authority.

## Implementation notes

Keep the managed token in runtime memory only. Do not persist it in config, logs, telemetry payloads, or generated files. If the device is revoked or membership/policy is stale, the server remains authoritative and the client must not retry privileged work blindly.
