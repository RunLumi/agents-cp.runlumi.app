## Outcome

A deterministic budget/rate-limit engine supports scoped soft/hard limits, bounded reservations, expiry, reconciliation, and obvious concurrent overspend protection using a D1-first contract.

## In scope

- Scope matching for organization, project, user/service, and model alias.
- Soft/hard decision and fail-closed unavailable state.
- Reservation amount calculation, commit/release/expiry transitions.
- Request/token/concurrency policy evaluation helpers.
- Pure race-case test model for conditional persistence.

## Explicitly out of scope

- SQL/D1 adapter calls, Durable Objects, billing, provider invoice reconciliation, and UI.

- Policy schema: P05 budgets/rate sections; hard cloud state unavailable fails closed.

## Implementation notes

Reservations must be integer minor units or bounded token estimates, never floating-point authoritative money. A D1 conditional write is the baseline; do not introduce a Durable Object without a measured serialization need and ADR.

## Acceptance criteria

- [ ] Most restrictive applicable scope wins.
- [ ] Hard limits cannot be bypassed by stale pre-request spend checks.
- [ ] Reservations are bounded, expiring, and monotonic through commit/release/expiry.
- [ ] Reconciliation is idempotent and cannot commit more than reserved without a new reservation.
- [ ] Unavailable hard-budget state fails closed only for eligible cloud work.
