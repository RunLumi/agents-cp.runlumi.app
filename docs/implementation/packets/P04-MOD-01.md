## Outcome
Provide pure catalog types, capability validation, lifecycle transitions, stable aliases, and organization allowlist decisions without coupling them to SQL or HTTP.

## In scope
- Provider, endpoint, model, alias, capability, and lifecycle types.
- Catalog allowlist and policy filtering rules.
- Unit tests for lifecycle, capability, and stable-ID behavior.

## Explicitly out of scope
- D1 SQL, HTTP handlers, provider network calls, and frontend rendering.

## Implementation notes
Provider display names are mutable metadata. Route selection uses stable provider/model IDs and capability predicates, never display text.

## Acceptance criteria
- [x] Disabling a provider/model excludes it from new routes.
- [x] Stable IDs survive display-name changes.
- [x] Required capabilities exclude incompatible candidates.
- [x] Org allowlists are explicit and default-deny when a policy explicitly lists values; project scope is preserved only from the trusted P03 snapshot.
