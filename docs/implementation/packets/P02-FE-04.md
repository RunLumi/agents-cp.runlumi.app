## Outcome

Everyday signup/login UX clearly presents passkey first and email/password second, with graceful browser fallback and no regression to accessibility/performance.

## Scope

Primarily:

- `apps/web/src/features/auth/**`;
- focused auth API client/types;
- account security/passkey management UI where needed.

## Required sign-in hierarchy

```text
[ Sign in with passkey ]       <- primary

----------- or -----------

Email
Password
[ Sign in with email ]         <- secondary

Forgot password?
```

Normal email one-time-code sign-in is removed from the everyday login panel after backend support is ready. Email codes remain in verification/recovery screens.

## Required signup hierarchy

Primary passkey CTA first, then email/password fallback.

Passkey signup may collect email/name as account/recovery metadata before invoking WebAuthn creation.

## Browser behavior

- Use `navigator.credentials.create/get` through a minimal tested adapter.
- Feature-detect WebAuthn.
- Where supported, use conditional mediation/autofill for login.
- A username/email field used for conditional mediation should use `autocomplete="username webauthn"`.
- User cancellation is not treated as a catastrophic error.
- Unsupported browsers/contexts surface the password form immediately without dead-end messaging.
- Never store WebAuthn ceremony state or auth secrets in localStorage.

## Account security

Expose passkey metadata:

- label;
- created/last used;
- add passkey;
- revoke passkey with consequence/recent reauth.

Prevent last-login-method removal in both UI and backend.

## Acceptance

- [ ] Passkey is visibly first on signup and login.
- [ ] Email/password is second.
- [ ] Keyboard/focus/screen-reader behavior works.
- [ ] Conditional mediation is progressive enhancement only.
- [ ] Cancelled native passkey prompt returns user to usable auth form.
- [ ] Password-manager autofill works.
- [ ] No normal login path asks for email OTP after passkey/password support ships.
- [ ] No browser auth secret is persisted client-side.

## Performance

Do not add a heavy WebAuthn frontend dependency if the browser API plus a small adapter is sufficient.
