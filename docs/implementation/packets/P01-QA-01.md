## Outcome

Provide reproducible checks for the frozen contracts, actual local D1 migration/retry behavior, and the browser-to-Worker persistence/outbox path without using remote customer resources.

## In scope

- `apps/api/tests/**`, `apps/api/scripts/**`, and focused web API-client tests under `apps/web/src/lib/**`.
- Contract fixtures/snapshots for API errors, health/meta, request IDs, idempotency, and event envelope.
- A smoke harness that starts local Worker/web or clearly documents the exact commands and bounded prerequisites.

## Explicitly out of scope

- Editing Rust implementation modules owned by MOD/BE packets, project manifests/config, central router/entrypoint, or production infrastructure.
- Flaky network tests, real Cloudflare accounts, production databases/queues, or customer data.

## Frozen contracts consumed

- P01-CG error envelope/status codes, IDs/time, pagination, idempotency, and event envelope.
- P01-MOD Rust serialization types.

- P01-BE-03 middleware response/logging behavior.
- P01-FE API client and development probe behavior; FE owns web client tests.

## Implementation notes

- Local D1/Queues must be isolated and deterministic. Never point tests at remote resources.
- The smoke path proves web → Worker → request ID → D1 commit → outbox → consumer/test delivery → user-visible result.
- Duplicate key/body replays without duplicate mutation/outbox; same key/different fingerprint conflicts.
- Logs in fixtures assert absence of raw body, auth header, secret, and full event payload.
- Keep prerequisites explicit and preserve all existing repository changes.

## Acceptance criteria

- [ ] Contract tests fail if error envelope or request ID behavior drifts.
- [ ] Clean local migration applies and migration history is visible.
- [ ] Duplicate idempotency request creates exactly one persisted mutation/outbox event.
- [ ] Outbox consumer/test delivery reaches a stable terminal state and is idempotent under repeat delivery.
- [ ] Web-visible result reflects actual local D1 state; mocks are not used for the Integration Gate.
- [ ] `pnpm check`, `pnpm build`, Rust WASM build, and Worker dry-run commands are integrated and reproducible.

- [ ] authorization centralized — no client-side authority assertions
- [ ] no secret/token leakage in fixtures
