## Outcome

Provide a thin D1 adapter and repositories using prepared statements and transactional batches, with an append-only Wrangler migration history for idempotency and outbox infrastructure.

## In scope

- `apps/api/src/adapters/d1/**` and `apps/api/src/repositories/**`.
- `apps/api/migrations/**`: initial schema only for idempotency and outbox invariants.
- Local/test migration fixture notes and deterministic repository tests where the binding harness permits.

## Explicitly out of scope

- Every future product table, generic ORM, read replication, R2, or Durable Objects.
- Queue consumer/publisher behavior beyond the D1 repository port.
- Changes to Wrangler, Cargo, root package scripts, app router, or CI.

## Write surface

Allowed paths:

```text
apps/api/src/adapters/d1/**
apps/api/src/repositories/**
apps/api/migrations/**
```

Shared files requiring coordinator approval:

- `apps/api/Cargo.toml`, `apps/api/wrangler.jsonc`, `apps/api/src/app.rs`, and migration manifest/config are coordinator-owned.

## Frozen contracts consumed

- Persistence: P01-CG table names, IDs, UTC timestamps, idempotency uniqueness/scope/expiry, outbox envelope/state.
- D1: prepared statements and `batch()` for invariants; do not depend on read replicas.
- Error boundary: map binding errors outside the domain layer; never expose SQL/provider details.

## Implementation notes

- Wrangler D1 migrations are the applied-version ledger. Migration files are immutable after application; changes append a new numbered file.
- D1 batch is the transaction boundary for business mutation + outbox + completed idempotency response.
- Avoid SQL assembled from untrusted table/order/filter identifiers.
- Put no sensitive body, key value, or token in logs/snapshots.
- Report any `worker` crate feature/dependency needed; coordinator owns manifest edits.
