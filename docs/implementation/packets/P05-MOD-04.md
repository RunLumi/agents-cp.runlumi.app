## Outcome

Immutable usage and cost records explain historical spend after pricing changes, reconcile inference and run sources idempotently, and exclude prompt/response content.

## In scope

- Usage source/reconciliation value objects.
- Cost calculation record with pricing source/version/effective time.
- Idempotent usage/cost projection rules.
- Rollup input normalization and safe redaction.
- Reconciliation conflict reasons.

## Explicitly out of scope

- Provider invoice APIs, billing plans, D1 SQL, charts, and raw content storage.

## Frozen contracts consumed

- Events: `usage.recorded.v1`, `usage.reconciled.v1`.
- Policy schema: pricing version and budget decision fields from P04.

## Implementation notes

A recalculation is a new immutable CostRecord with `calculation_kind=recalculated`; never update an old price-derived value. Preserve provider usage as bounded metadata and redact content fields.

## Acceptance criteria

- [ ] Every usage event is attributable to org/project/principal/request/run where available.
- [ ] Same reconciliation identity replays without duplicate cost rows.
- [ ] Conflicting external reconciliation returns a stable error.
- [ ] Historical cost remains explainable after catalog pricing changes.
- [ ] No prompt/response/tool content enters usage or cost payloads.
