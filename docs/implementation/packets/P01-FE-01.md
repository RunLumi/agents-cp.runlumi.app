## Outcome

Give later feature routes a small typed API client and an accessible application-level error boundary that presents stable error codes and request IDs without parsing server prose.

## In scope

- `apps/web/src/app.tsx`, `apps/web/src/lib/api.ts`, and focused `apps/web/src/lib/**` error/client support.
- Loading, global 401/403/404/500/unknown states; request ID visible on errors; user-controlled retry for retryable failures.
- Small development-only foundation-check UI that uses the frozen internal route when enabled; no route or data assumptions in production.
- Tests for parsing success/error/malformed responses and request ID display.

## Explicitly out of scope

- Feature-specific screens, query cache/state framework, organization selection behavior, new component library, or global store.
- Dependencies and changes to root/frontend manifests, Vite config, or Wrangler.

## Frozen contracts consumed

- P01-CG JSON errors and `X-Request-ID`.
- `/api/health` and `/api/v1/meta` fixtures.
- Development-only foundation-check POST/status response shapes.

## Implementation notes

- Client branches on HTTP status and stable `error.code`; never on English message text.
- Unknown/malformed errors show a generic message and preserve `X-Request-ID` when present.
- Keep initial route JavaScript small; no data-query dependency is selected by an ADR.
- Every async view has intentional loading, success, empty, and error behavior; keyboard/focus remain visible.
- Do not render an internal test control in production mode.
