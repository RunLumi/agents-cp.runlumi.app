## Outcome

Map built-in, plugin, and custom ZCode MCP sources to stable Lumi tool identities/fingerprints and re-evaluate new or changed tools before managed execution.

## In scope

- Source/type mapping for built-in/plugin/custom MCP registrations.
- Stable registration ID and tool fingerprint derivation.
- Non-secret endpoint/command metadata and allowed-origin propagation.
- Re-review behavior when a plugin/MCP update adds or changes a tool.
- Unknown-tool default deny/review path.

## Explicitly out of scope

- MCP server implementation, secret storage/rotation, and general plugin marketplace behavior.

## Implementation notes

Use non-secret metadata only. A stable source identity is not sufficient for approval: the tool fingerprint/list must be part of the decision binding. A changed fingerprint returns to review even if the display name is unchanged.

## Acceptance criteria

- [ ] Built-in/plugin/custom sources map to stable IDs without name-only collisions.
- [ ] New tools under an existing registration cannot inherit old approval silently.
- [ ] Secret handles are never returned or logged.
- [ ] Custom destinations pass allowlist/SSRF policy before registration or use.
- [ ] Unknown privileged tools fail closed in managed mode.
