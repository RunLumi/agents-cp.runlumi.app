# Work Packet — P02-MOD-05: Passkey and password credential domain

- Phase/lane/status: P02 additive / MOD / ready
- Owner: unassigned
- Depends on: P02-CR-002, P02-CG `p02-cg-v2`
- Blocks: P02-BE-05, P02-QA-02
- Specs/ADRs: F01, F05, F16, F23; ADR 0002/0005
- Contract amendment: P02-CR-002

## Outcome

A small domain model defines authenticator semantics without leaking WebAuthn library types or Cloudflare details through the application.

## Scope

Primarily `apps/api/src/modules/identity.rs` or a narrowly named sibling auth module.

Define:

- PasskeyCredential metadata/state;
- PasswordCredential metadata/state;
- WebAuthnCeremony kinds/states;
- authenticator add/remove lockout guard;
- recent-reauth requirements;
- security-event names;
- stable auth errors/reasons;
- rules for synced-passkey signature counters.

## Out of scope

- cryptographic WebAuthn verification;
- KDF implementation;
- D1 migrations;
- HTTP handlers;
- UI.

## Acceptance

- [ ] Passkey is modeled as a credential, not as an email identity.
- [ ] Multiple passkeys per user are allowed.
- [ ] The last usable login method cannot be removed accidentally.
- [ ] Ceremony lifecycle is one-time, short-lived, and kind-bound.
- [ ] Usernameless login maps verified credential -> user; client user ID is not authority.
- [ ] Zero/non-incrementing counters do not automatically reject synced passkeys.
- [ ] Domain types contain no raw password/private key.

## Tests/security

Unit-test state transitions, lockout prevention, duplicate/revoked credential rules, and counter semantics.

## Handoff

P02-BE-05 may rely on these invariants but remains responsible for maintained verifier/KDF compatibility.
