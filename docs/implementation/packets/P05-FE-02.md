## Outcome

Expose a readable capability/risk matrix, MCP registrations, browser/computer policy state, pending approvals, and recent allow/deny history with safe resolve actions.

## In scope

- API decoders for tool/MCP/policy/approval contracts.
- Tool policy matrix and MCP source/fingerprint/review state.
- Approval list/detail and approve/deny confirmation flows.
- Recent denied/approved events and empty/error/loading/permission states.

## Explicitly out of scope

- Executing tools, secret entry/reveal, browser/computer control, and run inference stream rendering.

## Implementation notes

Approval cards must show exact tool, risk class, run, and redacted arguments summary before a decision. Never provide a client-side “force allow” control. Re-review UI must appear when fingerprint/status changes.

## Acceptance criteria

- [ ] Matrix clearly distinguishes allow/session approval/per-use/deny.

- [ ] Approval decisions are permissioned, confirmed, idempotent, and auditable.

- [ ] Keyboard focus, narrow layout, and error states meet DESIGN.md.
