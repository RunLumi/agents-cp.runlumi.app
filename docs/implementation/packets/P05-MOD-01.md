## Outcome

Pure, server-side state-machine rules create append-only `Run` history, validate monotonic transitions, make cancel idempotent, and represent retry as a new attempt linked to the prior run.

## In scope

- `RunState` and `SessionState` enums with stable wire names.
- Transition validation and terminal-state guards.
- Retry attempt-number calculation and parent-link validation.
- Bounded RunEvent type/payload construction helpers.

## Explicitly out of scope

- HTTP routes, SQL persistence, inference dispatch, approval UI, and external client wiring.

## Frozen contracts consumed

- API: P05-CG AgentDefinition, Session, Run, RunEvent schemas and routes.
- Entities: `rse_`, `run_`, `rev_` ID and state definitions.
- Permissions: none in pure state machine.
- Events: `run.state_changed.v1`, `run.retried.v1`, `run.cancelled.v1`.
- Policy schema: current authorization is checked before invoking a transition.

## Implementation notes

Keep transitions pure and deterministic. A failed historical run must never be reopened by a retry or cancellation request. Require an explicit terminal state before accepting finished timestamps.

## Acceptance criteria

- [ ] Every documented state transition is accepted only from the allowed predecessor set.
- [ ] Terminal runs reject all non-idempotent mutations.
- [ ] Retry returns a new attempt ID/attempt number and preserves parent history.
- [ ] Cancel is idempotent and has one terminal result.
- [ ] RunEvent sequence is strictly increasing and bounded.
