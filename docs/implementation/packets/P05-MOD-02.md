## Outcome

A pure evaluator composes platform hard deny, organization/project policy, agent definition, runtime capability, tool fingerprint, and approval requirements into one explainable decision.

## In scope

- Risk-class and capability validation.
- Effective policy precedence and default-deny behavior.
- Unknown/new MCP tool fingerprint handling.
- Browser and computer-use policy evaluation.
- Redacted, bounded decision reasons and argument summaries.

## Explicitly out of scope

- Executing tools, storing secrets, HTTP routes, MCP transport, browser automation, and approval persistence.

- Policy schema: P03 `tools.schema_version: 1`; schema-0/malformed sections fail closed in managed mode.

## Implementation notes

The evaluator must be usable with both browser-session and device-token callers. It must never accept a client-supplied `allow` decision. Exact tool fingerprint and risk-relevant argument summary are part of the approval binding.

## Acceptance criteria

- [ ] Platform hard deny cannot be overridden.
- [ ] Unknown privileged tools default to deny/re-review in managed mode.
- [ ] New MCP fingerprints cannot inherit an old approval.
- [ ] Browser/computer restrictions are evaluated independently of prompts.
- [ ] Decisions are deterministic and explainable with stable reason codes.
