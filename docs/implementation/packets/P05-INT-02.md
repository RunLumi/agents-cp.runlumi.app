## Outcome

Before a managed privileged tool executes, the desktop/runtime asks the control plane for a policy decision, waits for the exact approval binding when required, and records the decision before proceeding.

## In scope

- Decision request/response types for run/tool-call correlation.
- Runtime broker hook before privileged shell/network/browser/computer/MCP actions.
- Approval polling/refresh and fail-closed behavior.
- Stable tool fingerprint and bounded arguments summary propagation.
- Local personal-mode bypass only when explicitly not managed.

## Explicitly out of scope

- Control-plane policy evaluator internals, approval persistence, and actual tool implementations.

## Implementation notes

The runtime must treat a missing, malformed, stale, or mismatched decision as deny. Approval is bound to exact tool ID/fingerprint/run/arguments summary. Do not send raw secret handles or full sensitive arguments to the control plane.

## Acceptance criteria

- [ ] Privileged action cannot proceed before a valid decision.
- [ ] Per-use approval binds to the exact call and cannot be replayed.
- [ ] Deny remains deny regardless of prompt/model output.
- [ ] Decision/approval failures are observable and do not leak sensitive payloads.
- [ ] Local personal mode is clearly separate from managed mode.
