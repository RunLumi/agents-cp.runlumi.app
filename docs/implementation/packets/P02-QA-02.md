# Work Packet — P02-QA-02: Passkey/password hostile and compatibility matrix

- Phase/lane/status: P02 additive / QA / ready
- Owner: unassigned
- Depends on: P02-MOD-05, P02-BE-05, P02-FE-04
- Blocks: P02 auth-upgrade integration gate
- Specs/ADRs: F01, F05, F16, F22, F23
- Contract amendment: P02-CR-002

## Outcome

Direct evidence proves passkey-first and password-fallback authentication is secure, compatible, accessible, and preserves shipped session/device behavior.

## Required passkey matrix

- [ ] signup registration succeeds;
- [ ] usernameless login succeeds;
- [ ] second passkey can be added;
- [ ] passkey can be revoked;
- [ ] last usable login method cannot be removed;
- [ ] challenge replay rejected;
- [ ] expired ceremony rejected;
- [ ] wrong RP ID rejected;
- [ ] wrong/unapproved origin rejected;
- [ ] bad signature rejected;
- [ ] missing required user verification rejected;
- [ ] unknown/revoked credential rejected;
- [ ] client-supplied user substitution cannot authenticate another user;
- [ ] synced passkey zero counter is not falsely rejected;
- [ ] meaningful counter anomaly follows documented security-event behavior.

## Required password matrix

- [ ] signup succeeds;
- [ ] login succeeds;
- [ ] wrong account/password uses generic failure;
- [ ] password rate limiting works;
- [ ] reset is one-time/expiring;
- [ ] reset/session revocation policy works;
- [ ] persisted value is slow-KDF output, never plaintext/fast raw hash;
- [ ] logs/errors/snapshots contain no password/reset token.

## Browser/UX matrix

At minimum test representative current Chromium, Safari/WebKit, and Firefox behavior where available:

- passkey supported;
- conditional mediation supported/unsupported;
- user cancels authenticator UI;
- WebAuthn unavailable/insecure context;
- password fallback remains accessible;
- keyboard/focus/narrow viewport;
- password manager/autocomplete;
- primary/secondary visual ordering.

## Compatibility matrix

- [ ] existing email verification still works;
- [ ] legacy email-code login remains compatible during migration;
- [ ] cookie/session/CSRF semantics unchanged;
- [ ] org/invitation authorization unchanged;
- [ ] desktop PKCE browser approval works after passkey auth;
- [ ] desktop PKCE browser approval works after password auth;
- [ ] P03/P04 principal/session integrations do not regress.

## Runtime evidence

Record:

- chosen WebAuthn verifier/version and WASM proof;
- password KDF parameters and Worker benchmark;
- Worker bundle delta;
- auth endpoint latency;
- any ADR created due runtime constraints.

## Exit

Do not mark the auth upgrade complete on mocked WebAuthn alone. At least one real browser authenticator ceremony must pass end-to-end in the target deployment environment.
