## Outcome

Expose tenant-scoped tool/MCP policy administration, current tool-decision broker evaluation, and approval create/list/resolve flows without executing privileged work in the Worker.

## In scope

- P05 tool/capability/MCP tables and repository.

- Exact tool/fingerprint/argument binding and current policy evaluation.
- Approval idempotency/version guards, expiry, and audit/outbox events.
- P03 policy snapshot `tools.schema_version: 1` integration.

## Explicitly out of scope

- Actual shell/browser/computer/MCP execution, secret resolution, inference provider calls, and UI.

## Implementation notes

The decision endpoint returns policy metadata only. It must not accept a client `allow` flag, raw secret, arbitrary tool URL, or unbounded arguments. Approval resolution checks current membership/project scope and exact fingerprint, then emits an event that the execution host can verify.

## Acceptance criteria

- [ ] Unknown/new privileged tools cannot inherit approval after MCP/plugin changes.
- [ ] Prompt/model/client headers cannot override deny.
- [ ] Cross-tenant tool/MCP/approval IDs are denied or not found indistinguishably.
- [ ] Approval resolution is idempotent and expires safely.
- [ ] Browser/computer policy denies are persisted and auditable.
- [ ] No secret or raw tool argument is returned/logged.
