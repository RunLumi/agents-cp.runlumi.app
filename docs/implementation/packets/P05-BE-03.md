## Outcome

Make usage/cost reconciliation, budget CRUD/reservations, and rate/concurrency policy authoritative, tenant-scoped, queryable, and safe under retries/concurrent spend.

## In scope

- Add P05 usage source/reconciliation and cost/rollup tables/columns.
- Budget and rate-limit repository/handlers using existing P04 tables where possible.
- Conditional D1 reservation writes, expiry/reconciliation, and idempotency projections.
- Usage ingest/reconcile, rollup queries, and budget-denial audit events.
- Connect P05 run/inference correlation to P04 usage and reservation records.

## Explicitly out of scope

- Provider invoice reconciliation, billing plans, chart rendering, and Durable Objects unless separately justified.

## Implementation notes

Do not create a second reservation system. Extend P04's existing tables and preserve immutable historical usage. Reservation writes must be conditional against current usage plus live reservations; use integer minor units and bounded token estimates.

## Acceptance criteria

- [ ] Concurrent eligible requests cannot trivially exceed a hard budget.
- [ ] Reservation/reconciliation transitions are idempotent and expiry-safe.
- [ ] Usage is attributable to org/project/principal/request/run/device where known.
- [ ] Historical cost retains pricing source/version and recalculation is append-only.
- [ ] Budget/rate queries are tenant-scoped and cursor bounded.
- [ ] Denials expose stable codes and emit audit events without sensitive bodies.
