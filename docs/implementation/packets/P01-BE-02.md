## Outcome

Add a durable D1-backed outbox dispatcher and idempotent Queue consumer so committed events can be retried and observed without coupling business success to downstream delivery.

## In scope

- `apps/api/src/modules/outbox/**`, `apps/api/src/adapters/queues/**`, `apps/api/src/consumers/**`, `apps/api/src/jobs/**`.
- Event serialization, bounded retry metadata/backoff, queue publisher port/adapter, consumer acknowledgement and dead-letter state handling.
- A bounded scheduled retry sweep over pending events; queue delivery remains at least once and consumer handling deduplicates by event ID.

## Explicitly out of scope

- Product notifications/webhooks, email, billing, inference, or user-facing event browsing.
- Editing the central Worker entrypoint, Wrangler config, D1 migration, Cargo manifest, or central HTTP router.
- R2, Durable Objects, or distributed tracing.

## Frozen contracts consumed

- Event envelope and outbox states in P01-CG.
- D1 outbox repository contract from P01-BE-01.
- Queue messages carry the full versioned event envelope; no request body or credential.
- Worker queue delivery is at least once; handler effects are idempotent by `event_id`.

## Implementation notes

- Commit the event to D1 before queue publication.
- Queue-send or consumer failure must leave durable retry/failure state.
- Use bounded exponential backoff with jitter and finite attempts; do not create unbounded retry loops.
- Do not log event payloads. Logs may include event ID, request/correlation IDs, attempt count, and stable error code.
- Report required Rust feature flags and binding names to the coordinator instead of editing shared config.

## Acceptance criteria

- [x] Outbox records are published only after committed persistence.
- [x] Dispatch retry is bounded and leaves an observable pending/dead-letter state on failure.
- [x] Consumer handling is idempotent by event ID and acknowledges only after durable completion.
- [x] Queue retry configuration is explicit and local configuration supports the same consumer path.
- [x] Duplicate queue delivery does not mark or apply the same event twice.
