# Work Packet — P02-BE-05: Passkey-first and password-fallback backend

- Phase/lane/status: P02 additive / BE / ready
- Owner: unassigned
- Depends on: P02-MOD-05, P02-CR-002, `p02-cg-v2`
- Blocks: P02-FE-04 integration, P02-QA-02
- Specs/ADRs: F01, F05, F16, F23; ADR 0002/0005
- Contract amendment: P02-CR-002

## Outcome

Rust Worker supports production-grade passkey registration/login as primary authentication and email/password as secondary authentication while preserving the shipped LoginSession/cookie/CSRF/desktop-PKCE contracts.

## Mandatory Step 0 — runtime compatibility spike

Before product implementation, prove the chosen maintained WebAuthn verifier and password KDF path:

1. compile for `wasm32-unknown-unknown`;
2. pass Worker dry-run/build;
3. verify a real WebAuthn registration + assertion with persisted server ceremony state;
4. benchmark the target password KDF under Worker CPU/memory constraints;
5. measure Worker bundle delta.

Do not manually implement WebAuthn cryptography.

Target new password storage is current OWASP Argon2id baseline or stronger. If that cannot safely run in this runtime, STOP and create an ADR for an alternative trusted verification boundary. Do not silently lower work factors or replace it with a fast hash.

## Scope

Likely write surfaces:

- `apps/api/src/routes/auth.rs` or focused passkey/password route modules;
- `apps/api/src/repositories/identity.rs` or focused credential repositories;
- additive D1 migration(s);
- `apps/api/src/app.rs` route registration under shared-file ownership;
- relevant auth tests/smoke fixtures.

Implement:

- passkey signup start/complete;
- usernameless passkey login start/complete;
- account passkey list/add/revoke;
- password signup/login/set/change;
- password forgot/reset;
- separate rate limits;
- immutable security events;
- reuse existing secure session creation/rotation;
- explicit trusted RP ID/origin configuration.

## Persistence

Additive schema must support:

- globally unique passkey credential ID;
- credential public verification material;
- user mapping;
- passkey metadata/revocation;
- one-time WebAuthn ceremony state + expiry/consume;
- one password KDF result per user with algorithm/parameters;
- recovery challenge state.

Never persist raw passwords, passkey private keys, raw session secrets, or raw reset tokens.

## WebAuthn security

Reject at least:

- replayed/expired ceremony;
- wrong challenge;
- wrong RP ID/hash;
- unapproved origin;
- missing required user verification;
- bad signature/public key;
- unknown/revoked credential;
- attempted client-selected user substitution.

Do not derive trusted RP ID/origin from arbitrary Host input.

## Password security

- slow KDF only;
- generic login/reset failure;
- independent rate limiting;
- password managers/paste supported by API limits;
- reset creates security event and applies explicit session revocation policy.

## Acceptance

- [ ] Passkey signup creates verified passkey + existing LoginSession only after WebAuthn verification.
- [ ] Passkey login works without email.
- [ ] Password signup/login works as fallback.
- [ ] Existing email verification remains usable.
- [ ] Existing legacy email-code flow remains compatible until separately deprecated.
- [ ] Desktop PKCE approval works after passkey/password browser auth.
- [ ] No auth secret appears in logs/errors/idempotency rows.
- [ ] WASM/build/performance evidence is recorded.

## Stop conditions

Stop for ADR/review if no maintained WebAuthn verifier or acceptable password KDF path can be proven in the Rust Worker runtime.
