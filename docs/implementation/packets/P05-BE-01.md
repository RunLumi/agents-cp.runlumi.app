## Outcome

Persist and expose tenant-scoped AgentDefinition, Session, Run, append-only RunEvent, and ArtifactRef resources with authorized start/cancel/retry and cursor-paginated timeline APIs.

## In scope

- Migration `0010_p05_runs_tools_usage_control.sql` run/session/artifact tables.
- Repository queries/mutations for the P05-CG run APIs.
- Thin Axum handlers, validation, CSRF/idempotency/version guards, and audit/outbox integration.
- Current P03 project/device/policy checks at run start and resume.
- Device-token run identity propagation and local-only/managed dispatch boundary.

## Explicitly out of scope

- Tool execution, approval resolution, budget/rate persistence, usage dashboards, and frontend components.

## Frozen contracts consumed

- API: P05-CG AgentDefinition/Session/Run/RunEvent/Artifact routes.
- Entities: `agd_`, `rse_`, `run_`, `rev_`, `art_` records.
- Permissions: `agents.*`, `sessions.*`, `runs.*`, plus P02/P03 scope checks.
- Events: `agent_definition.*`, `session.*`, `run.*`, `artifact.created.v1`.
- Policy schema: P03 project/device/policy snapshot; P04 alias/route.

## Implementation notes

Keep handlers thin. `POST /runs` must authorize the current project/device and reject stale or caller-selected policy authority. A run's `agent_session_id` is P05-owned; P04 `session_id` remains the P02 login session. Use D1 batches for state transition + RunEvent + audit/outbox writes.

## Acceptance criteria

- [ ] Cross-org IDs and restricted-project runs deny without existence leaks.
- [ ] State transitions are server-validated and append-only.
- [ ] Retry creates a new run; prior run history is unchanged.
- [ ] Cancel is idempotent and propagates a cancellation signal/event to the execution host.
- [ ] Run timelines expose bounded metadata and no prompt/secret bodies.
- [ ] Archived projects/devices/membership changes block new starts and require current checks on retry.
