## How a stale device is refused

The lease token lives in a `#token` private field, so it is not an enumerable
property: `JSON.stringify`, structured logging, and error serialization cannot
emit it. The only way out is `buildFenceRequest`, which always stamps the fence
the server most recently confirmed — a stale caller cannot even express a stale
request.

`assertFenceCurrent` is a three-way comparison rather than an equality check:

- a different `lease_id` is `automation_lease_fence_unknown`;
- a version/fence **behind** the held one is `automation_lease_fence_stale`
  (the lost-renewal case);
- a version/fence **ahead** of anything observed is also
  `automation_lease_fence_unknown`, because "newer" is not "authoritative".

`#adoptFence` makes the fence monotonic, so a delayed renewal cannot resurrect a
superseded fence. `assertSideEffectAuthorized` is the single side-effect gate and
fails closed in `idle`, `claimed`, `ambiguous`, `settled`, and `released` —
`claimed` is refused because a claim proves a lease, **not** a run link.
`assertToolResultAllowed` additionally requires the reported `run_id` to equal
the granted one. `markAmbiguous()` is terminal.

Provider side: `createAutomationManagedRunContextFromGrant` accepts
`Omit<ManagedRunContextInput, "runId" | "agentSessionId">`, so the start grant is
the only source of the run link, and it reuses the existing opaque-ID validator
so P05's fail-closed approval behaviour is untouched.

## Unsafe local paths deliberately not reused

- `AutomationRepo.claimDue` (local boolean single-flight) — no fence, no
  `ambiguous`, no server authority.
- `OffPeakTaskRepo.recoverInterrupted` (`running → queued`) — asserts a
  partitioned host produced no side effect, which a partition cannot prove.
  Replaced by `classifyInterruptedAutomationOccurrence`, whose result union has
  **no `requeued` member**; the type is the assertion and an exhaustive-switch
  test enforces it.
- The scheduler's local 5-minute `MISFIRE_GRACE_MS` — the recovery observation
  carries no misfire value, only server facts plus the lease expiry. A test
  proves ±1h of clock skew can only flip `continue ↔ releasable` and can never
  manufacture authority.
- `buildRunId`'s colon-delimited local run IDs — refused by
  `isServerMintedLumiRunId`; test fixtures use only gate IDs.
- The V4 in-memory transport log is untouched: P06 recovery is server-side and
  durable, not a conversation delta log a restart resets.

## Finding: the off-peak/automation tool denylist has FOUR divergent copies

Two are genuine correctness divergences, not just duplication:

| Copy | Automation set | Off-peak set |
|---|---|---|
| `packages/services/src/zcode-agent/automationToolPolicy.ts` | `CronCreate, CronUpdate, CronDelete` | **`OffPeakCreate` only** |
| `apps/zcode-cli/packages/core/src/runtime/methods/turn-loop-state.ts` | same | `OffPeakCreate, SendMessage, Workflow` |
| `apps/zcode-cli/packages/bootstrap/src/zcode-protocol-v4/commands/prompt-turn.ts` | same | `OffPeakCreate, SendMessage, Workflow` |
| `apps/zcode-cli/packages/bootstrap/src/zcode-protocol/server-operations.ts` | **`CronCreate` only** | `OffPeakCreate, SendMessage, Workflow` |

1. `automationToolPolicy.ts` omits `SendMessage`/`Workflow`, so a host using
   only the services-layer policy would expose them on an off-peak turn.
2. `server-operations.ts` omits `CronUpdate`/`CronDelete`. Verified directly: a
   model that is refused `CronCreate` can still see `CronDelete` on the legacy
   protocol path, which is exactly the fallback the adjacent comment says the
   denylist prevents.

Canonical source is `turn-loop-state.ts` (core enforces at the tool-execution
boundary via `isOffPeakCreateRestrictedTurn`, and its
`OFF_PEAK_MUTATION_TOOL_NAMES[0]` sentinel is load-bearing in the denylist
fallback). All four copies should import `P06_AUTOMATION_RESTRICTED_TOOL_NAMES`
and `P06_AUTOMATION_MUTATION_TOOL_NAMES` from `@zcode/shared`, where this
packet published the canonical values with a value test. All four files are
outside this packet's write surface, so they were left unchanged.
