# Work Packet Handoff — P01-BE-03

## What changed

Added request/correlation middleware, bounded structured timing logs, a normalized stable API error envelope for handler and Axum extractor failures, server-generated request IDs, and a one-MiB JSON extractor limit.

## Contracts consumed

- Contract Gate commit: `7835fd9` (`p01-cg-v1`)
- APIs: `ApiError`, error status/code map, `X-Request-ID`
- Permissions: identity placeholder remains anonymous; no authorization added
- Events: request and correlation IDs available to handlers
- Schema/policy versions: none

## Contracts produced

- `RequestContext` inserted into Axum request extensions
- `request_boundary` middleware and `json_body_limit`
- `ApiError: IntoResponse` helper preserving safe handler details while binding the trusted request ID
- Framework rejection normalization preserving safe `Allow`, `Retry-After`, and `WWW-Authenticate` headers

## Database/migration impact

- Migration: none
- Indexes/constraints: none
- Rollback/forward strategy: transport-only implementation; no persistence

## Runtime/deployment impact

- New bindings/env/secrets: none
- Worker compatibility: uses workers-rs Web Crypto, Date, and monotonic performance APIs at the boundary
- Client-version assumptions: clients use machine error codes, not messages

## Tests added

- In-memory Axum tests cover request/correlation context, request-ID spoofing, route/method errors, extractor errors, payload limits, redaction, and matched route logging.
- Rust suite: 47 passed; Clippy with warnings denied passed.

## Known limitations

- Authentication middleware remains a placeholder; tenant routes do not exist in P01.
- Logging is bounded structured console output; hosted telemetry ingestion and SLO instrumentation remain later operations work.

## Downstream agent notes

Handlers read request-scoped context using `Extension<RequestContext>` and use `ApiError` for stable errors. The boundary always overwrites `X-Request-ID` with its trusted generated value.

## Do not assume

- Inbound `X-Request-ID` is trusted.
- Client-supplied org/resource IDs prove authorization.
- The raw request body or arbitrary URI path is safe for logs.
