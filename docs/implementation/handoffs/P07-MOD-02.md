# Work Packet Handoff — P07-MOD-01..04

## What changed

Four domain modules, one per plan07 lane, plus the two typed-ID kinds they needed
and the third credential scheme ADR 0007 requires.

- `modules/plugins.rs` — the manifest, the eight-class permission diff, org
  policy (allow/block/pin/publisher mode/update mode), install review state, and
  the two decision functions. `PluginFacts::install_decision` answers "may this
  organization install it" and `execution_decision` answers "may this installed
  thing run"; they are separate because they are asked at different times by
  different callers, and F13 default-deny has to hold for the second one
  independently of the first.
- `modules/machine_identity.rs` — `CapabilitySet`, `ApiKeyScope`, and
  `authorize_machine` with a six-step check order that is stated in the module
  and pinned by tests.
- `modules/staff.rs` — `StaffRole`, `StaffPermission`, `SupportGrant`, and
  `authorize_staff`. The five human-only permissions are refused before scope is
  consulted.
- `modules/rollouts.rs` — `FeatureFlag` with stable-hash cohort assignment,
  `KillSwitch` with organization-before-global precedence, and the resolution
  enums that say *why* something is off rather than only that it is.

`core/machine.rs` gained the in-crate SHA-256 the Worker needs for key
derivation, with the published FIPS vectors as its test — `platform::sha256_hex`
is `async` and the derivation is a pure domain function, so it cannot use it.
`core/staff.rs` gained the third credential scheme.

## Known limitations

- **`metadata.google.internal` is not refused as a network destination.** The
  check is on the host literal by design — a hostname that resolves inward later
  must still be a declaration an operator can see — and `.internal` is not a
  reserved suffix, so a literal blocklist is a policy decision the gate has not
  made. Asserted explicitly in
  `a_private_or_loopback_destination_is_refused_at_report_time` so the gap is
  visible rather than inferred.
- A `*.suffix` pattern rooted at a three-octet string (`*.0.0.1`) is treated as a
  hostname, because it is not an IP literal and the literal-based check has no
  basis to call it private. Also asserted.
- `PluginDenyReason::VersionNotPendingReview` has the code
  `version_not_pending_review` while the other ten are `plugin_*`. It is
  deliberate — it is a precondition failure rather than a plugin refusal — and it
  is pinned by a test so nobody "fixes" it by accident.

## Downstream agent notes

- `diff` normalizes both manifests to sorted sets before comparing. Any
  consumer that re-sorts is duplicating that; any consumer that does not
  normalize will report an ordering change as a capability change.
- A class with entries on both sides is reported `added`, not a third verdict.
  This is the whole reason `expands` is a boolean rather than a score.
- `install_decision` and `execution_decision` are not redundant. Do not collapse
  them to save a call site.
- `scope_from_stored` takes the SERIALIZED arrays, not bare values, and `null`
  means "every project" while `[]` means "none". The first version of the fixture
  test fed it a bare id and failed with `InvalidInput` for exactly that reason.

## Do not assume

- That a `PluginPermissionManifest` field is optional because it has a
  `#[serde(default)]` on the struct. The eight manifest fields are all REQUIRED
  at the report boundary — a default there would turn a missing declaration into
  a silent no-capability one.
- That `rejects_destination` is only about IP ranges. It also refuses
  non-`http(s)/ws(s)` schemes, a missing scheme on a non-wildcard destination, and
  a pattern with no host in it.
- That staff authority can be expressed as a `MembershipRole`. It cannot, and
  there is no conversion in either direction. That is ADR 0007's load-bearing
  claim, and it is a compile-time fact.
