# Work Packet Handoff — P01-BE-01

## What changed

Added a narrow D1 adapter using prepared statements and `D1Database::batch`, plus append-only Wrangler migration `0001_p01_foundation.sql` and repositories for idempotency records and outbox events. A claim guard, application writes, outbox insert, and completed replay result are committed in one D1 batch.

## Contracts consumed

- Contract Gate commit: `7835fd9` (`p01-cg-v1`)
- APIs: idempotency lookup/replay/conflict semantics
- Permissions: no authorization is performed in a repository
- Events: outbox stores the versioned event envelope
- Schema: `idempotency_records`, `outbox_events`; Wrangler owns its migrations table

## Contracts produced

- `D1Adapter::{new, prepare, batch, changes}` with a closed set of bound SQL values
- `IdempotencyRepository` for active lookup, claim SQL, completion, atomic success transaction, and bounded expired cleanup
- `OutboxRepository` for event insert, due-pending reads, state transitions, and delivery lookup

## Database/migration impact

- Migration: `apps/api/migrations/0001_p01_foundation.sql`
- Indexes/constraints: unique idempotency scope `(principal_id, organization_id, method, path, key_digest)`, expiration index, event primary key and delivery-status/next-attempt index
- Rollback/forward strategy: Wrangler migration history is append-only. Repair by a new forward migration. Production restore requires a separately documented backup/restore procedure.

## Runtime/deployment impact

- New bindings/env/secrets: D1 binding `DB`; Wrangler `migrations_dir` is `./migrations`
- Worker compatibility: enable workers-rs `d1` feature; prepared statements use D1 bindings and batch semantics
- Client-version assumptions: none

## Tests added

- Local Wrangler migration applied; subsequent migration list returned no pending migrations. The final smoke reclaimed an expired key while preserving an active pending claim.
- `pnpm smoke:local` verified one persisted outbox event after duplicate replay and isolated different principal/org scopes; same exact scope insert was ignored.
- Repository SQL also validated against the migration during implementation for claim/reclaim, completion, stale-claim rollback, retry scheduling, and terminal-state protection.

## Known limitations

- Local D1 evidence is not remote production migration or restore evidence.
- P01 has no product tables and does not introduce read replication, R2, or Durable Objects.

## Downstream agent notes

Use the prepared-statement adapter and D1 batch for any mutation/outbox/idempotency invariant. Pass owner IDs from trusted application context, never client assertions.

## Do not assume

- Read replicas are used.
- Reusing an expired idempotency key replays the old result.
- A successful Queue send is transactional with D1.
