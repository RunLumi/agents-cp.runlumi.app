# Work Packet Handoff — P07-FE-01/02/03

## What changed

Two Settings sub-pages, 26 source files and 6 test files, registered in
`org-dashboard.tsx` and covered by `section-routing.test.ts`.

- `features/identity/` — service accounts and API keys. The capability picker is
  a closed list with no wildcard and a live plain-language scope preview; the
  one-time secret reveal is a pure reducer so the invariant is testable without a
  DOM.
- `features/plugins/` — installed/approved/blocked, the permission diff, version
  state, pin, block reason, and tool registration.

Two areas the gate calls out explicitly:

- **The one-time secret is structurally unrepeatable.** `reveal` is the only
  action that can put a secret into state and only the create and rotate response
  handlers dispatch it, so a list refresh, a re-read, a re-render, a back
  navigation, and a remount all dispatch nothing. `acknowledge` is terminal.
  Nothing is written to `localStorage`, `sessionStorage`, a cookie, the URL, or a
  log — asserted, not asserted-by-convention.
- **An expansion reads as an expansion.** `expansionHeadline` names the growing
  class in the summary, not only in a row further down, and `expansionDetail`
  states "a reduction does not offset a gain" whenever a diff both grew and
  shrank. This is the failure P07-CG calls out by name: a reviewer reading
  "networking was reduced", concluding the update is a tightening, and approving
  a version that gained a tool.

Every decoder is an allowlist that copies named fields and never spreads, so a
future server revision that started adding `secret` to a list or get projection
could not reach component state.

## Known limitations

- **No P07 surface has been rendered in a browser.** None is attached to this
  session. Desktop and narrow layout, computed colours, and the real appearance
  of focus rings are visually **unverified**. This is the same debt P06 carries
  and it is the single most important thing a reviewer should check first.
- `docs/screens/` has **no reference** for service accounts, one-time key reveal,
  plugin tables, a permission diff, or a pin/block dialog. Only
  `lumi_rate_limits.webp`, `lumi_plan_entitlements.webp`, and
  `lumi_account.webp` were usable, and they are the density and token reference
  rather than a layout reference for these surfaces.
- **Deviation from F22, recorded not hidden.** F22 is authoritative for the
  organization tree and places neither surface. `Plugins` and
  `Identity & access` are added as Settings sub-pages. `Identity & access` is
  deliberately *not* named F22's `Security / Identity`, because that name is
  about human sign-in and SSO, which P07 does not implement — reusing it would
  promise a surface that does not exist. If F22 later adds explicit pages,
  relocating is a Change Request.
- A keyboard trap (roving tabindex with no arrow-key handling) was found during
  development and fixed. It is recorded here because the class of bug is easy to
  reintroduce in a hand-built primitive with no Base UI to inherit from.

## Downstream agent notes

- `fixtures/p07-contracts-v1.json` is importable from the web app by relative
  path, the same way `p06-contracts-v1.json` is. Prefer extending it over
  hand-writing a new body in a test: a hand-written body is whatever the author
  believed, so the decoders and the server can drift together and every test
  still passes. That drift is not hypothetical — it is how `key_prefix:
  "lumik_0123456789ab"` and `fingerprint: "sha256:0123456789abcdef"` survived in
  the identity tests, neither of which is a shape the server produces.
- The stored `key_prefix` is **twelve lowercase hex characters** and the
  `fingerprint` is **sixteen**. The `lumik_` scheme prefix belongs on the wire
  value the create response returns once, and nowhere else.
- A stored `review_reason` is `"<event id> <summary json>"`. Match the event id
  as a PREFIX and read the payload; comparing the whole string to the bare id
  matches nothing the server writes.
- Route-level code splitting is in place: `identity-panel` 16.6 KiB gzip and
  `plugins-panel` 16.7 KiB gzip, both well under the 80 KiB route-chunk budget.
  Initial JS is 100.1 KiB gzip (budget 170) and initial CSS 8.7 KiB (budget 35).

## Do not assume

- That a hand-written test body proves a contract. It proves the decoder accepts
  what the test wrote.
- That `isPendingReview` takes a list item. It takes an **install**.
- That an expansion reason renders as a sentence by default. It did not, until
  this phase; `pendingReviewReason` now reads the payload, and three cases in
  `contracts.test.ts` pin that plus its degradation paths.
