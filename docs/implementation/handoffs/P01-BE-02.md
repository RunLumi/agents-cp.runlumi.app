# Work Packet Handoff — P01-BE-02

## What changed

Added an outbox delivery state model, D1 store port, bounded exponential retry with deterministic jitter, immediate publisher, scheduled retry sweep, idempotent Queue consumer skeleton, dead-letter handling, and structured redacted logs.

## Contracts consumed

- Contract Gate commit: `7835fd9` (`p01-cg-v1`)
- APIs: versioned event envelope and development delivery status
- Permissions: event metadata is not authorization evidence
- Events: at-least-once Queue envelope keyed by `event_id`
- Schema/policy versions: outbox schema from migration `0001_p01_foundation.sql`

## Contracts produced

- `OutboxStore` state-transition port implemented by the D1 repository
- `EventPublisher`, `EventHandler`, `OutboxConsumer`
- `dispatch_committed_record` and bounded `run_retry_sweep`
- Cloudflare Queue publisher, main/DLQ batch consumer, and redacted `OutboxLogger`

## Database/migration impact

- Migration: consumes `0001_p01_foundation.sql`; no new tables
- Indexes/constraints: delivery state and attempt-count compare-and-set operations use existing indexes
- Rollback/forward strategy: outbox states are forward transitions; replay requires an explicit safe operation in later product packets

## Runtime/deployment impact

- New bindings/env/secrets: `OUTBOX_QUEUE`, queue consumer, dead-letter queue names, one-minute scheduled retry trigger
- Worker compatibility: workers-rs `queue` feature; D1 remains canonical
- Client-version assumptions: only the development status response is surfaced in P01

## Tests added

- Retry bounds, jitter, dead-letter threshold, failure-code validation, payload-redaction checks
- Sequential duplicate-delivery test proves one handler application and a duplicate acknowledgement
- `pnpm smoke:local` confirmed actual local Queue consumer delivery reaches persisted `delivered` state
- Rust suite: 47 tests passed; Clippy and WASM checks passed

## Known limitations

- The fixture consumer handles only `foundation.check.requested.v1`; product event handlers are later phase work.
- Queue delivery is at-least-once. Product handlers must atomically deduplicate side effects by event ID or make effects idempotent.
- Hosted queue configuration and production queue monitoring were not exercised.

## Downstream agent notes

Write the D1 event/outbox transaction first. Publish only after D1 commit. Consumers must durably finish or schedule a bounded retry before acknowledging.

## Do not assume

- Queue send plus D1 commit is one atomic operation.
- Queue delivery is exactly once.
- A logged failure string is safe to persist; map failures to `FailureCode` first.
