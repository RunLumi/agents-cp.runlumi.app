# Work Packet Handoff — P07-BE-02/03/04

## What changed

The HTTP surface for the three implemented P07 areas, mounted in `app.rs`:
22 routes over three modules, plus the two authentication boundaries in
`http/auth.rs` that let a machine or a staff principal reach them at all.

- `routes/machine_identity.rs` — 9 routes. Service accounts (list, create, get,
  patch, suspend, resume) and API keys (list, create, get, rotate, revoke), plus
  `/api/v1/machine/whoami`.
- `routes/plugins.rs` — 9 routes. Overview, detail, policy read/patch, install,
  approve, block, unblock, pin, permission diff, and report.
- `routes/internal.rs` — 6 routes under `/api/v1/internal/*`: feature flags,
  kill switches, support grants.
- `http/auth.rs` — `require_machine` and `require_staff`.

Migrations `0017_p07_plugin_governance.sql` and
`0018_p07_platform_operations.sql`, and 13 data classes added to
`modules/data_governance/registry.rs` so P06's F20-001 discipline holds.

## Contracts consumed

- Contract Gate commit: `p07-cg-v1`; ADR 0007.
- APIs: the gate's §API contract, path for path.
- permissions: the four P07 permissions for the customer-facing routes;
  `StaffPermission` for `/internal/*`. **No route accepts both.**
- events: `plugin.permission_expansion_detected`, `api_key.created`,
  `api_key.rotated`, `api_key.revoked`, `service_account.created`, and the staff
  audit pair.
- schema/policy versions: `0016`, `0017`, `0018`.

## Contracts produced

- 22 mounted paths. The two that resolve their organization from the row rather
  than the path — `GET /api/v1/api-keys/{api_key_id}` and
  `POST /api/v1/api-keys/{api_key_id}/rotate|revoke` — take no `org_id`, so a
  caller cannot name an organization it does not belong to.
- `blocked_reason` on both install projections, which is what makes F25-004's
  "the conflict is reported rather than resolved" legible to an operator.
- `review_reason` in the frozen shape `<event id> <summary json>`.

## Database/migration impact

- migration: `0017_p07_plugin_governance.sql`, `0018_p07_platform_operations.sql`.
  Both apply after `0016` and before nothing.
- indexes/constraints: the load-bearing ones are triggers, not indexes. A revoked
  key's reason cannot be blanked, a revoked grant's reason cannot be blanked and
  it cannot be restored in place, a lifted kill switch cannot be re-engaged in
  place, a lifted grant needs a reason, and a flag must expire. Each is proven
  **rejected by the database itself** — see the harness below.
- rollback/forward strategy: forward-only. `0017`/`0018` create new tables; no
  P07 migration alters a P02–P06 table, so a rollback is dropping the new tables
  and no pre-P07 data is at risk.

## Runtime/deployment impact

- new bindings/env/secrets: none. No new binding, no new secret, no new env var.
- Worker compatibility: every D1-backed handler carries `#[worker::send]`. This
  is not optional decoration: without it the `Handler` bound fails with
  `the trait Handler<_, _> is not implemented` and **no note at all**, because the
  anonymous `!Send` future is inside a `js_sys::JsFuture` and rustc cannot name
  it. Two handlers were lost to this before the cause was found.
- client-version assumptions: none. The web client and the API ship together.

## Known limitations

- **`/api/v1/internal/*` has no web client.** The gate's decision 4 puts the
  staff console out of P07's scope. The routes, the boundary, and the audit
  exist; nothing renders them. This is why `routes/internal.rs` needed its own
  tests — there is no decoder on the other side to catch a projection mistake.
- F06 (SSO/SCIM/domains) is frozen-not-built. No route, no schema. The seam
  exists because P06 already seeded `sso.enabled`/`scim.enabled` defaulting
  `false`.
- No support console and no impersonation route. F24-003's "default mode is
  metadata, not impersonation" is met by absence.
- `Option<Query<T>>` is not usable as an axum extractor's last position; the list
  routes use `Query<T>` with `#[serde(default)]`.

## Downstream agent notes

- Two writes that must be one batch, and are: block/unblock moves the install
  review state **and** the policy block list together, and rotation creates the
  replacement **before** marking the prior key rotated. A reader who only looks
  at one table will think there is a window in which the org has no working key.
- `change_policy` / `write_policy` take `extra_write: Option<D1PreparedStatement>`
  so a caller can fold its own write into the same batch. Use it rather than
  issuing a second statement.
- The `#[worker::send]` requirement applies to *any* handler that touches D1. A
  verbatim copy of a working handler, truncated after its first call, fails
  identically to a from-scratch handler — the error is not about your code.

## Do not assume

- That a `pub` function in a route module is mounted. `copy_of_budgets` was a
  diagnostic probe that outlived its purpose; it is deleted. Grep `app.rs`, not
  the module, to know what is mounted.
- That `#[serde(default)]` on a request body field makes it optional at the
  domain layer. It makes it optional in parsing only.
- That an audit event alone is a record. The second real defect this phase found
  was `POST /plugins/{package_id}/block` writing the reason **only** to the audit
  event while `plugin_installs.blocked_reason` sat empty — a column that existed,
  was never written, and is what an operator actually reads.
